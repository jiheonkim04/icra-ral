# ECHO-VLA Counterfactual Data Protocol

Date: 2026-07-11 KST

## Definition

ECHO may use the words `counterfactual` and `interventional` only for samples generated by same-state action interventions.

For a fixed official LIBERO simulator state `s_t`:

1. sample `K` candidate action chunks from the same frozen SmolVLA policy or a predeclared candidate generator;
2. restore exactly the same simulator state before every candidate;
3. execute every candidate for the same fixed horizon `H`;
4. observe its realized physical effect;
5. record `(observation, instruction, inferred/training phase, candidate action chunk, realized effect)`.

Ordinary demonstration transitions are not counterfactual pairs.

## Same-State Requirements

Each intervention group must store:

- `group_id`;
- suite, task id, reset seed, step index;
- initial simulator state hash before each candidate;
- observation hash before each candidate;
- candidate index;
- action chunk;
- fixed horizon;
- post-execution effect vector;
- whether the candidate ended early due success/termination/truncation;
- policy/candidate source.

The exact-state restoration test passes only when all candidate start-state hashes in a group are identical.

## Candidate Sampling

Initial candidate count: `K=4`.

Candidate sources, in priority order:

1. frozen SmolVLA stochastic samples if the official policy interface permits sampling without changing the backbone;
2. frozen SmolVLA default chunk plus small bounded perturbations;
3. default chunk plus queue-prefix variants only when they are produced before observing candidate effects.

No candidate may use future reward, test success, or oracle effect labels.

## Training / Deployment Separation

Privileged simulator state is allowed only to generate labels. Deployment uses:

- current images;
- proprioception;
- instruction;
- history;
- candidate action chunk.

Deployment must not use:

- ground-truth object pose;
- simulator state;
- BDDL success evaluator;
- future effect labels;
- task success/reward as a gate input.

## Required Validation Checks

- exact-state restoration test;
- counterfactual-pair identity test;
- no-test-privilege test;
- effect-label schema test;
- candidate-headroom calculation test.

## Failure Conditions

The protocol fails if:

- state hashes differ inside an intervention group;
- candidate effects are read before candidate selection;
- test rollout success is used to tune thresholds;
- a reported counterfactual pair is only two neighboring demonstration transitions;
- privileged labels are used in the online selector.
