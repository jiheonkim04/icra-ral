## Closest Three Current Papers

### 1. AFIL

URL: https://arxiv.org/abs/2605.08434

Overlap:

- failure trajectories used as negative guidance;
- success and failure action behavior modeled separately;
- VLA flow/diffusion action generation targeted;
- closed-loop success and robustness are the claim axis.

Difference claimed by FANG:

- AFIL trains dual action generators for the policy itself.
- FANG keeps the frozen SmolVLA base action as the default action, learns success/failure action fields, and derives a bounded residual with a validation-calibrated gate.
- FANG must compare against an `afil_local_proxy` that uses the same trace data and dual action-field heads but removes the identity-preserving validation gate.

Reviewer risk:

If FANG beats Base but not the AFIL proxy, the claimed technical difference is unsupported. If FANG only works by making larger residuals, it is not identity-preserving and should be killed or reclassified as design failure before confirmatory rollout.

### 2. A2C2

URL: https://arxiv.org/abs/2509.23224

Overlap:

- lightweight correction head;
- base action is an explicit input;
- chunk index/phase matters;
- intended to preserve base competence while improving closed-loop control.

Difference claimed by FANG:

- A2C2 targets real-time observation correction for chunk reactivity.
- FANG targets success/failure negative guidance and must prove that the failure residual contributes beyond a success-only correction head.

Reviewer risk:

If the failure residual is unnecessary and the method is just a time-aware residual correction head, novelty collapses to A2C2-like local correction.

### 3. DREAM-Chunk / Pre-VLA / VeriSpace Boundary

URLs:

- https://arxiv.org/abs/2606.18589
- https://arxiv.org/abs/2605.22446
- https://arxiv.org/abs/2606.10568

Overlap:

- policy reliability is improved around action chunks;
- additional learned modules use execution evidence, candidate evaluation, or validity/advantage signals;
- all report positive VLA reliability improvements.

Difference claimed by FANG:

- FANG does not sample multiple chunks, rank candidates, verify safety, or resample actions.
- It modifies the executed 7D action by a bounded residual from a trained success/failure field.

Reviewer risk:

If FANG's gate becomes a generic verifier that only decides whether to accept or reject action changes, or if implementation requires candidate generation, it drifts into an occupied verifier/ranker family and must be stopped. A discovery-only field-separation gate target is acceptable only as an integration-safety mechanism, not as the paper novelty by itself.

## Simplest Equivalent Methods

### Equivalent 1: Success-Only Residual

Train only `m_plus(x_t)` and apply:

`a'_t = clip_action(a_t + alpha * G_t * clip_delta(m_plus(x_t) - a_t))`.

If this matches FANG, failure-aware negative guidance is unnecessary.

### Equivalent 2: Nearest-Success Replay

Use the nearest successful same-task record and blend toward its action under the same residual bound.

If this matches FANG, the learned action-field mechanism is not adding method value over CAVM's strongest simple baseline.

### Equivalent 3: Unconstrained AFIL Proxy

Use the same success/failure heads but no validation-calibrated identity-preserving gate:

`a'_t = clip_action(a_t + alpha * clip_delta((m_plus(x_t) - a_t) + beta * (m_plus(x_t) - m_minus(x_t))))`.

If this beats FANG, the identity-preserving contribution is performance-negative and the method is not a stronger honest design.

## Data And Objective Risks

1. Existing trace actions were generated by frozen SmolVLA. FANG must train action-field heads against logged actions, not residual targets formed by subtracting each row's action from itself. If target variance collapses, FANG is a `DATA_FAILURE`.
2. Terminal success labels are coarse. Failed episodes can contain locally useful approach actions. The failure residual must be reliability-gated, not treated as a universal repulsion signal.
3. The success class is much smaller than the failure class. Class balancing and per-task coverage must be audited before training.
4. A trained head can memorize identity or task/reset geometry. The split must block identity overlap and report per-task validation.
5. A residual trained from logged frozen actions may learn common action statistics rather than corrective directions. The nearest-success and success-only baselines are therefore mandatory.

## Mathematical Risks

- No KL divergence is justified between deterministic 7D actions.
- The dual heads do not define probability distributions unless a density model is explicitly normalized; do not write probabilistic claims that the implementation cannot support.
- Huber losses may have different class magnitudes. The audit must estimate term values and gradient norms on a small batch.
- The gate can saturate to zero or one. If it is always zero, the module is nonacting; if it is nearly always one, identity preservation failed. The gate target must be computed from discovery/validation traces only and frozen before confirmatory rollout.
- Clean retention cannot be inferred from small action L2 alone; it must include validation behavior and closed-loop clean checks when available.

## Leakage Risks

- Do not train, validate, calibrate, or select configurations on confirmatory identities.
- Do not use CAVM Stage 2A/2B/expansion result rows as FANG training data.
- Do not use simulator object state, BDDL predicates, intermediate rewards, terminal success of the current test episode, or held-out identity membership at inference.
- Do not choose tasks, thresholds, or reset identities after seeing FANG confirmatory outcomes.
- Do not report AFIL as reproduced; label the baseline `afil_local_proxy`.

## Required Reviewer Conditions

Proceed to implementation only if preregistration includes:

1. exact discovery, validation, and confirmatory identity partitions;
2. a pre-experiment headroom/data/mechanism/disruption audit;
3. exactly five first-comparison policies;
4. fixed bounded validation search with at most six configurations;
