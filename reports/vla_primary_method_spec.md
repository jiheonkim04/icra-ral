# ECHO-VLA Primary Method Specification

Date: 2026-07-11 KST

Selected method: `ECHO-VLA`, Counterfactual Effect Credit for Closed-Loop VLA Manipulation.

No experiment, implementation, model inference, GPU work, simulator execution, training, or download occurred.

## 1. Paper Working Title

`ECHO-VLA: Counterfactual Action-Effect Credit for Closed-Loop Vision-Language-Action Manipulation`

## 2. Core Problem Statement

VLA policies are commonly trained to match expert actions using token likelihood, L1 regression, or flow matching, but closed-loop robot success depends on whether each action chunk causes the physical predicate transition required by the current task phase. A chunk can be likely, smooth, semantically aligned, and geometrically plausible while still failing to produce the needed effect.

## 3. One-Sentence Contribution

ECHO-VLA introduces a phase-conditioned counterfactual effect objective that estimates the causal predicate effect of candidate action chunks and uses this estimate to train and guide VLA action generation toward closed-loop success.

## 4. Key Hypothesis

Training a VLA with counterfactual action-effect credit will improve closed-loop task success, especially under controlled execution perturbations, because the policy learns which action chunks change the world in the task-relevant way rather than merely matching expert action coordinates.

## 5. Why The Hypothesis Is Plausible

Recent VLA papers improve action generation, verification, confidence, progress, correction, and robustness, yet most still optimize proxy objectives. The literature repeatedly exposes a gap between offline action quality and closed-loop success. LIBERO-style tasks also expose task predicates that can provide supervised effect labels during training. These labels can be distilled into image/proprioception models so deployment does not require privileged state.

## 6. Why Existing Methods Cannot Directly Solve It

- OpenVLA-OFT improves action representation and throughput but still uses action regression.
- ProgVLA and ProgressVLA inject progress, but progress is scalar or future-latent based, not a vector of phase-required physical predicate effects.
- AFIL uses failure trajectories as negative guidance, but does not isolate the causal effect of an action chunk under matched context.
- Pre-VLA, CoVer, and VeriSpace verify or rank candidates, but the learned score is validity, confidence, alignment, safety, or advantage rather than interventional predicate effect.
- VLA-Corrector fixes drift during execution, but does not train the base action representation to assign closed-loop credit.

## 7. Method Overview

ECHO-VLA augments a VLA with an effect-credit module. During training, short chunks are paired with labels describing how task-relevant predicates changed after execution. Matched counterfactual chunks are generated by perturbing, replacing, or reusing alternative actions under the same observation, instruction, and phase. The model learns `P(effect | do(action_chunk), observation, instruction, phase)`. During inference, the VLA proposes one or more chunks and ECHO scores or guides them by expected phase-required effect.

## 8. Module-by-Module Design

1. Phase memory `Z`.
   - Parses instruction into phase-relevant predicate requirements.
   - Maintains current phase from visual predicate estimates and previous predicted effects.

2. Visual predicate estimator `Q_psi`.
   - Predicts task predicate vector from images and proprioception.
   - Trained from simulator/BDDL predicate labels but used without simulator state at deployment.

3. Counterfactual effect model `E_phi`.
   - Inputs: observation embedding, instruction embedding, phase token, proprioception, and action chunk.
   - Outputs: distribution over predicate deltas plus uncertainty.

4. Effect-guided policy interface.
   - For continuous action backbones, reranks small candidate sets or applies differentiable guidance when available.
   - For flow backbones, adds effect guidance during denoising or post-sampling reranking.

5. Logging and calibration.
   - Records predicted effect, selected chunk, realized predicate estimate, latency, and intervention count for evaluation.

## 9. Mathematical Notation

- `o_t`: visual/proprioceptive observation.
- `l`: language instruction.
- `z_t`: current phase token.
- `a_t^H`: action chunk of horizon `H`.
- `s_t`: privileged simulator state during training only.
- `p(s_t) in {0,1}^M`: task predicate vector.
- `e_t = p(s_{t+K}) - p(s_t)`: realized predicate-effect vector.
- `r(z_t) in {-1,0,1}^M`: phase-required effect vector.
- `E_phi(o_t,l,z_t,a_t^H)`: predicted effect distribution.

## 10. Full Training Objective

Base imitation:

`L_BC = ||a_t^H - a_t^{H,*}||_1` for continuous heads, or the existing token/flow objective for the backbone.

Effect prediction:

`L_eff = CE(E_phi(o_t,l,z_t,a_t^H), e_t)` for binary predicate deltas plus optional Huber loss for continuous distances.

Counterfactual ranking:

Given positive chunk `a+` and matched counterfactual `a-` under the same `(o_t,l,z_t)`,

`A_e(a) = r(z_t)^T E_phi(o_t,l,z_t,a) - beta ||a||_smooth`

`L_rank = max(0, margin - A_e(a+) + A_e(a-))`.

Effect-invariant regularization:

Chunks that differ in action coordinates but produce the same predicate effect are pulled together:

`L_inv = ||g_phi(a_i) - g_phi(a_j)||_2` when `e_i = e_j`.

Full objective:

`L = L_BC + lambda_eff L_eff + lambda_rank L_rank + lambda_inv L_inv + lambda_cal L_cal`.

Calibration term `L_cal` is expected calibration error or Brier loss on predicted effect probabilities, not task-success confidence.

## 11. Inference Algorithm

1. Encode current observation and instruction.
2. Estimate current predicate vector with `Q_psi`.
3. Update phase token `z_t`.
4. Generate `N` action chunks from the VLA. Prototype can use `N=4`; an ablation uses `N=1`.
5. Predict effect distribution for each chunk.
6. Select or guide the chunk with highest expected phase-required effect minus smoothness/latency cost.
7. Execute the selected prefix.
8. Re-estimate predicates and update phase memory.

## 12. Pseudocode

```text
for each control decision t:
    h_t = encode_vla_observation(o_t, l)
    p_hat_t = Q_psi(o_t)
    z_t = update_phase_memory(l, p_hat_t, history)
    candidates = VLA.sample_chunks(o_t, l, N)
    for a in candidates:
        e_hat[a], u_hat[a] = E_phi(o_t, l, z_t, a)
        score[a] = dot(r(z_t), e_hat[a]) - beta * cost(a) - kappa * u_hat[a]
    a_star = argmax(score)
    execute_prefix(a_star)
    history.append(o_t, z_t, a_star, e_hat[a_star])
```

## 13. Training Supervision

- Expert action chunks from official demonstrations.
- Predicate deltas from task success predicates, BDDL-derived logical predicates, and simulator state labels.
- Matched counterfactual chunks from small perturbations, wrong-phase chunks, nearest-neighbor alternate chunks, and bounded future simulator rollouts in the later implementation goal.
- No human labeling is required for the first prototype beyond verifying predicate extraction.

## 14. Data-Generation Process

Future implementation should generate a small effect dataset:

1. Load official LIBERO task definitions and demonstrations.
2. Segment trajectories into chunk windows.
3. Extract predicate state at `t` and `t+K`.
4. Construct counterfactual chunks:
   - jittered expert chunk,
   - wrong object/phase chunk from same suite,
   - nearest action chunk with different predicate effect,
   - optional short simulator rollout of candidate chunks.
5. Store `(observation, instruction, phase, chunk, effect_label, predicate_label)`.

## 15. Whether Simulator Labels Are Needed

Yes for training and evaluation labels. They are not needed at inference. This is acceptable because the method is a training-signal contribution, and privileged simulator labels are explicitly removed at deployment by distillation into `Q_psi` and `E_phi`.

## 16. How Deployment Remains Non-Privileged

Deployment uses only camera images, proprioception, language, generated action chunks, and learned visual predicate/effect estimators. No simulator state, BDDL evaluator, success oracle, ground-truth object pose, or privileged contact label is queried online.

## 17. Integration With SmolVLA

SmolVLA is the preferred first prototype backbone because it is locally efficient. Integration path:

- keep SmolVLA policy unchanged for frozen baseline,
- add an external ECHO effect head over SmolVLA image/action embeddings,
- optionally train a small adapter for candidate generation only after the effect head beats baselines,
- report latency and VRAM overhead separately from the SmolVLA policy.

## 18. Integration With OpenVLA-OFT INT4

OpenVLA-OFT INT4 is the second backbone path. Integration path:

- use the quantized OpenVLA-OFT policy as an action-chunk proposer,
- run ECHO as a separate lightweight scorer on generated chunks,
- avoid treating quantization as contribution,
- verify that the selected effect axis persists despite the stronger OpenVLA-OFT baseline.

## 19. Parameter Count

Prototype estimate:

- visual predicate estimator: `5M-20M` trainable parameters depending on encoder reuse,
- effect model: `3M-15M`,
- phase memory/projection layers: `<2M`,
- total new trainable parameters: expected `<40M`.

## 20. Expected VRAM / Runtime

Prototype on RTX 5080:

- SmolVLA frozen inference plus ECHO head: expected within existing local memory.
- ECHO head training: expected `<8GB` VRAM with cached embeddings or small batches.
- OpenVLA-OFT INT4 plus ECHO scoring: expected to fit under the already verified quantized path with modest overhead, but must be confirmed in the implementation goal.

## 21. Latency Overhead

Expected overhead:

- `N=1`: `5-15 ms` effect scoring after cached embeddings.
- `N=4`: `20-60 ms` plus candidate generation cost.
- Full report must include policy forward passes, ECHO forward passes, VRAM, and wall-clock latency.

## 22. Failure Modes

- Predicate labels are too coarse to distinguish real physical effects.
- Visual predicate estimator fails under occlusion or lighting shift.
- Counterfactual chunks are unrealistic and teach spurious differences.
- ECHO reranking improves effect metrics but not task success.
- Simple progress/value/verifier baseline matches ECHO.
- Stronger OpenVLA-OFT INT4 baseline removes targeted condition.
- Latency cost offsets success gains.

## 23. Difference From Closest Three Papers

### Pre-VLA

- Problem level: Pre-VLA checks action validity before execution; ECHO trains action-effect credit.
- Representation level: Pre-VLA outputs safety confidence and critic advantage; ECHO outputs phase-conditioned predicate-effect deltas.
- Objective level: Pre-VLA uses focal classification, advantage regression, and calibration; ECHO uses counterfactual effect prediction and matched-context ranking.
- Inference level: Pre-VLA filters/resamples low-quality chunks; ECHO scores or guides chunks by required causal effect.
- Experimental level: ECHO's main axis is closed-loop success under effect-critical perturbations, not generic verification quality.

### ProgressVLA / ProgVLA

- Problem level: progress papers address progress awareness; ECHO addresses causal action-effect credit.
- Representation level: progress is scalar or critic-like remaining horizon; ECHO is a vector of physical predicate deltas.
- Objective level: progress guidance/weighted imitation differs from interventional matched-counterfactual ranking.
- Inference level: ECHO can choose a nonmonotonic chunk if it causes the next required predicate effect.
- Experimental level: ECHO must report effect-validity and perturbation success, not only long-horizon progress.

### CoVer / VeriSpace

- Problem level: CoVer and VeriSpace verify alignment or spatial validity; ECHO learns the expected physical consequence of an action.
- Representation level: verifier embeddings and 3D geometry are not predicate-effect deltas.
- Objective level: contrastive alignment/geometric reasoning differs from `P(effect | do(action), context)`.
- Inference level: ECHO can be used with one candidate or small candidate sets; candidate selection is not the novelty.
- Experimental level: ECHO must beat verifier-style reranking on closed-loop task success and effect-specific metrics.
