# Action Decoder Landscape

This note is a planning document for the low-compute TCA-Map pilot. It is not a literature-survey result table. Exact paper details, model sizes, benchmark numbers, and GPU-hour estimates are marked **needs manual verification** when they are not available inside this repository context.

## Decoder Families

| Family | Core idea | What decoder changes | Compute cost | RTX 5080 16GB compatibility | Helps target grounding? | Training or inference | Comparison baseline | Use / do not use |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| ActionMap / voxel action heatmap | Predict a spatial or voxelized action likelihood map, then decode an action from heatmap peaks. | Replaces direct continuous regression with a heatmap head plus action decoding. | Low to moderate for low resolution; high for full-resolution voxel maps. Exact costs need manual verification. | Compatible if heatmaps are low-resolution or coarse-to-fine. Avoid full-resolution voxel grids locally. | Yes, if heatmap is conditioned on target or language and evaluated on wrong-target behavior. | Mostly training-time head change plus inference-time decoding. | Native continuous head, TCA-Map, ActionMap + counterfactual augmentation. | Use as required baseline because TCA-Map may otherwise look like ActionMap plus target head. |
| OpenVLA-OFT continuous L1 regression head | Fine-tune or adapt a VLA with a continuous action head optimized by L1-style action regression. | Keeps action output continuous rather than voxelized. | Potentially high for full fine-tuning. Exact local memory depends on checkpoint and precision; needs manual verification. | Full OpenVLA-OFT training is not compatible with local policy. Frozen/load smoke only unless separate approval changes this. | Indirectly, through language-conditioned features, but no explicit target heatmap by default. | Training-time adapter or fine-tune path. | Native OpenVLA-OFT head, SmolVLA native head. | Keep as paper-grade target baseline, but do not run large local experiments. |
| CF-VLA coarse-to-fine action generation | Generate actions in coarse-to-fine stages, first narrowing action/space region, then refining locally. | Adds multi-stage coarse and local refinement decoder. | Moderate to high depending refinement depth and simulator/data pipeline; needs manual verification. | Compatible only in a small scaffold if coarse grids remain low-resolution and refinement is local. | Likely useful for target grounding when refinement is target-conditioned, but details need manual verification. | Training-time decoder design and inference-time refinement. | ActionMap, TCA-Map low-res only, TCA-Map coarse-to-fine. | Consider as optional local refinement, not first implementation. |
| Discrete Diffusion VLA | Model action generation through discrete diffusion over action tokens or bins. | Replaces single-step action decoding with iterative denoising. | Usually higher inference cost due to multiple denoising steps; exact costs need manual verification. | Risky on 16GB for real VLA backbones unless very small and cached. | May help multimodal actions; target grounding impact needs manual verification. | Both training-time objective and inference-time sampler. | Native head, autoregressive action expert, diffusion action decoder. | Do not use for first local pilot; keep as landscape context. |
| TBD-VLA temporal block diffusion | Diffuse blocks of temporally extended actions rather than a single action. | Adds temporal block action decoder and diffusion schedule. | High relative to head-only single-step decoding; needs manual verification. | Not a first RTX 5080 16GB target unless tiny/cached. | Could improve temporal consistency; target grounding effect needs manual verification. | Training-time and inference-time method. | Single-step VLA head, diffusion decoder, temporal action decoder. | Do not use in the low-compute pilot. |
| AR-VLA autoregressive action expert | Decode action tokens autoregressively, often with causal next-token prediction. | Converts action output into an action-token sequence. | Moderate to high due to autoregressive decoding length; needs manual verification. | May fit only for small models or cached features; not ideal for the first heatmap method. | Can condition each token on language, but target geometry is less explicit than heatmaps. | Training-time decoder plus inference-time autoregressive sampling. | Native continuous head, FAST tokenization, MG-Select-style AR selector. | Useful comparison conceptually, but Distributional TCA-Select does not claim superiority on AR VLAs. |
| ACoT / Coarse-to-Control | Use action chain-of-thought or coarse control stages before final low-level action. | Adds intermediate action reasoning/control tokens or stages. | Varies widely; exact details need manual verification. | Possibly compatible if intermediate heads are small and backbone frozen. | Potentially helps if intermediate target references are explicit. | Training-time supervision plus inference-time staged decoding. | Native head, coarse-to-fine decoder, TCA-Map local refinement. | Not first implementation; may become a future ablation. |
| StructVLA | Add structured scene/object/action representations inside the VLA policy. | Decoder may consume explicit structure or output structured action/state elements. | Needs manual verification. | Compatibility depends on structure extractor and model size. Avoid heavy extra modules locally. | Likely relevant to target grounding if structure identifies objects. | Mostly training-time architecture/data method. | Native VLA, scene-graph or object-aware policy, TCA-Map target heatmap. | Document as related, not first pilot. |
| EvoScene-VLA | Use evolving scene representations for VLA decision making. | Decoder conditions on scene evolution or temporal scene state. | Needs manual verification. | Risky locally if it requires heavy scene modules or long context. | Potentially helps target persistence; exact claim needs manual verification. | Training-time architecture and inference-time state tracking. | StructVLA, temporal VLA, native VLA. | Do not use in first low-compute method. |
| ProgressVLA / ProgVLA | Condition action prediction on task progress or progress-aware representations. | Adds progress signal/head or progress-conditioned decoder. | Needs manual verification. | Potentially compatible if progress head is small and features are cached. | Helps stage grounding more than object target grounding unless target-aware. | Training-time supervision and inference-time conditioning. | Native VLA, progress-conditioned ablation. | Consider only after target/action grounding is measured. |
| Residual correction decoder | Predict a residual correction on top of a base policy action. | Keeps base decoder and adds small corrective head. | Low if backbone is frozen and correction head is small. | Compatible with RTX 5080 16GB. | Can reduce action error, but target grounding only improves if correction is target-conditioned. | Training-time head plus inference-time correction. | Native head, TCA-Map head-only, ActionMap. | Useful fallback if heatmap decoding underfits, but not core novelty. |
| Action prior pretraining | Pretrain action distributions or priors before task adaptation. | Adds an action prior module/objective used by decoder. | Dataset-dependent; needs manual verification. | Compatible only if using small local cached datasets. | Indirect target grounding unless prior is target-conditioned. | Training-time pretraining. | No-prior head-only, native head. | Do not use before real asset path is stable. |
| FAST action tokenization | Tokenize continuous actions into compact action tokens for efficient sequence modeling. | Replaces continuous outputs with tokenized action representation. | Can be efficient at inference, but exact tokenizer/model details need manual verification. | Potentially compatible for small token heads, but not the current heatmap path. | Target grounding depends on how tokens preserve action geometry. | Training-time tokenization and inference-time token decoding. | Continuous head, AR-VLA, native action token decoder. | Track as alternative decoder, not first Distributional TCA-Map implementation. |

## Takeaway

The low-compute branch should not chase every decoder family. The publishable path is to keep the backbone frozen, use low-resolution target-conditioned action heatmaps, and add Distributional TCA-Select as a verifier-free inference-time selection rule. Alternative decoders are either baselines, future ablations, or related work that needs manual verification before making paper claims.
